# Silero VAD 入力ウィンドウ方式の実測比較検証(P0-1)

## 背景

`SileroVadDetector`は、公式実装(512サンプルhop・64サンプル文脈・非重複ウィンドウ)とは異なる
ウィンドウ方式(480サンプルhop・576サンプル連続スライディングウィンドウ)を採用している。
これはこのアプリの音声取得ループが30ms(480サンプル)周期で動いており、公式仕様の512サンプル単位とは
端数が合わないための設計判断だった。

コードレビュー(GitHubレビューP0-1「Silero VADの入力方式を最優先で再検証」)の時点では、
「Silero VAD自体は連続音声にロバストな設計であり実用上の精度に大きな影響は無いと考えられるが、
モデルが学習時に見ていない入力分布(重複96サンプル vs 公式64サンプル)を与え続けていることになり、
これは実際の音声で確率曲線を比較しない限り白黒つけられない」という理論上の懸念にとどまっていた。
本ドキュメントは、その懸念を実測で検証した結果をまとめる。

## 検証方法

- `SileroVadDetector`に`useOfficialWindowing`パラメータを追加し、同一クラス内で
  アプリ既定方式(`false`、本番で使用)と公式方式(`true`、この検証専用)を切り替えられるようにした。
- `LoopbackRecorder.Tests/VadWindowingComparisonTests.cs`で、同じ音声ファイルを両方式に
  まったく同じチャンク列・同じタイミングで通し、以下を比較した:
  1. 発話確率曲線(30msごとの値)の最大差・平均差
  2. `VoiceActivitySegmenter`(既定パラメータ: EnergyThreshold=0.5, HysteresisRatio=0.6)を通した
     結果の検出区間数
  3. 区間ごとの開始/終了時刻のズレ
- テスト音声: PowerShell(`System.Speech.Synthesis.SpeechSynthesizer`)による日本語TTS音声
  (「こんにちは、今日はいい天気ですね。」「それではゲームを始めましょう。」の2発話、無音を挟む)

## 結果

| ファイル | 確率曲線の最大差 | 確率曲線の平均差 | 検出区間数(既定/公式) | 境界時刻の最大ズレ |
|---|---|---|---|---|
| sample1.wav (TTS音声) | 0.4301 | 0.0115 | 2件 / 2件(完全一致) | 30ms(=1チャンク分) |

区間ごとの詳細:

```
区間1: 開始差=0ms   終了差=-30ms (既定: 00:00.12-00:03.06, 公式: 00:00.12-00:03.09)
区間2: 開始差=-30ms 終了差=0ms   (既定: 00:03.39-00:05.67, 公式: 00:03.42-00:05.67)
```

## 結論

**現行の実装(480サンプルhopのスライディングウィンドウ方式)を維持する。公式方式への切り替えは不要と判断する。**

根拠:

- 検出される発話区間の**件数は完全に一致**しており、「発話として検出するかどうか」という
  最終的な判断は両方式で変わらなかった。
- 境界時刻のズレは最大30ms(=このテストのチャンク周期そのものであり、比較の解像度の限界値)にとどまり、
  実際の字幕/翻訳表示のユーザー体験に影響する水準ではない。
- 確率曲線の最大差(0.43)は発話の立ち上がり/立ち下がり付近で一時的に生じているとみられるが、
  `VoiceActivitySegmenter`の`HysteresisRatio`による緩衝もあり、最終的な区間検出結果には
  影響していないことが確認できた。

以上により、コードレビュー時点の「実用上の精度に大きな影響は無いと考えられる」という判断は
実測で裏付けられた。

## 限界・今後の検証余地

- 今回の検証はTTS音声1ファイル(日本語、明瞭な発話)のみで行った。より多様な条件
  (小声・早口・BGM混入・ノイズの多いマイク環境など)での追加検証は行っていない。
  もし将来的にVADの誤検出・検出漏れが実運用で報告された場合は、該当の音声を
  `LoopbackRecorder.Tests/TestData/`に追加し、`VadWindowingComparisonTests`を再実行することで
  同様の実測比較ができる。
- `SileroVadDetector`の`useOfficialWindowing`パラメータはテスト専用であり、本番の
  `AudioPipeline`からは常に既定値(`false`)で呼び出される(変更なし)。
